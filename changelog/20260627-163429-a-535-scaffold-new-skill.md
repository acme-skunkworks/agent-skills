## Added

- **`scaffold-new-skill` meta-skill ([A-535](https://linear.app/acme-skunkworks/issue/A-535)).**
  A new `skills/scaffold-new-skill/` bundle that generates a spec-compliant
  skeleton for a fresh `skills/<name>/` bundle, so new skills stop drifting from
  the bundle contract. Given `--name=<kebab>`, the bundled zero-dependency
  `scripts/scaffold.mjs` writes a `SKILL.md` (frontmatter `name` = directory,
  `metadata.version` `0.1.0`, `metadata.author`), a `package.json`
  (`@acme-skunkworks/skill-<name>`, `private: true`, `version 0.1.0`,
  `repository.directory: "skills/<name>"`), a `config.json` + `config.example.json`
  generated from one template object (identical key sets by construction), an
  entry `scripts/<name>.mjs` wired to the standard `--help` / `--dry-run` /
  `--self-test` dispatch idiom, a `tests/skills/<name>/<name>.test.ts` stub (in the
  repo's already-globbed `tests/` tree, so no config change), and a `README.md` —
  every artefact passing the same `pnpm validate:skills` rules. The generator
  supports `--dry-run` (prints what it would write, creates nothing), `--self-test`
  (offline assertions over a temp dir), and refuses to overwrite a non-empty
  target. Bundled as `scaffold-new-skill@0.1.0`.
